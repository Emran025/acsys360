# 08 — مرجع Minimap وسلوك التنقل

## المرجع الرسمي

تصف [واجهة VS Code الرسمية][1] الـ Minimap بأنها عرض عالي المستوى للمصدر يساعد على الفهم والتنقل السريع. تظهر افتراضيًا على يمين المحرر، ويُستخدم الجزء المظلل الذي يمثل مجال الرؤية للنقر أو السحب للوصول إلى أقسام بعيدة من الملف. وتظهر أسماء folding markers، مثل تعليقات `//#region`، داخل الخريطة عندما تكون لغة المحرر داعمة لها.

تُظهر صفحة [Basic Editing][2] أن المحرر يجب أن يبقى موجهًا للتحرير أولًا، وأن التنقل والاختصارات والتمرير لا يجوز أن تعطل الإدخال أو التحديد. أما [Language Configuration Guide][3] فتربط بنية الملف بقواعد folding وindentation وon-enter.

## مواصفة Arabic360

| العنصر | التنفيذ المطلوب |
|---|---|
| موضع الخريطة | يمين مساحة الكود، لا يمين واجهة التطبيق كلها، وتبقى شجرة الملفات في جانبها الحالي |
| صورة الملف | أسطر مصغرة بألوان token categories، مع تمييز التعليقات والأسطر الفارغة والأقسام |
| القسم | يكتشف `برنامج` و`اجراء` وتعريفات `نوع` و`ثابت` و`متغير`، إضافة إلى العناوين داخل التعليقات العربية أو `#region` |
| مجال الرؤية | مستطيل مظلل يمثل أول وآخر سطر ظاهر في المحرر، ويتحرك مع ScrollController |
| النقر | يحول موضع y داخل الخريطة إلى line index ثم يقفز المحرر إلى ذلك السطر |
| السحب | يحافظ على تفاعل مستمر مع مجال الرؤية ويحدث scroll دون تعديل النص |
| المؤشر | نقطة أو خط صغير عند line المؤشر، مستقل عن viewport |
| التشخيص | علامات صغيرة للمشكلات على جانب الخريطة، بلون severity، دون إخفاء نص المصدر |
| التعليقات | شرائط أو نقاط أهدأ لونًا من الكلمات، وتُستخرج من النص دون تفسير محتوى التعليق كتعليمة |
| الأداء | إعادة بناء النموذج عند تغير النص أو diagnostics، لا إنشاء Widget لكل محرف في الملف |
| الوصولية | Tooltip، hit target مناسب، وتباين واضح، مع عدم احتجاز لوحة المفاتيح داخل minimap |

## قيود التصميم

الـ Minimap ليست محررًا ثانيًا ولا تعرض النص بحجم قابل للتحرير. لا تُنشئ selection أو completion، ولا تستولي على Focus عند النقر إلا بقدر تنفيذ scroll. وتظل ScrollController وTextEditingController مصدرَي الحقيقة؛ الخريطة تعرضهما ولا تملك نسخة مستقلة من النص.
