# 03 — قواعد اللغة ومراحل المترجم

## 1. القاعدة العامة للبرنامج

```text
برنامج اسم_البرنامج؛ {
  جزء_التعريفات
  قائمة_التعليمات
}.
```

يجوز أن تأتي فاصلة منقوطة ASCII أو عربية وفق ما يقبله lexer، وتظل الكلمات المحجوزة عربية كما هي. لا تُترجم الكلمات إلى بدائل إنجليزية داخل مصدر المستخدم.

## 2. التعريفات والأنواع

| العنصر | الصياغة المعتمدة |
|---|---|
| ثابت | `ثابت الاسم = القيمة؛` |
| متغير | `متغير الاسم: النوع؛` |
| نوع قائمة | `نوع الاسم = قائمة[العدد] من النوع؛` |
| نوع سجل | `نوع الاسم = سجل { الحقول }؛` |
| إجراء بالقيمة | `اجراء الاسم(بالقيمة الاسم: النوع)؛ { التعليمات };` |
| إجراء بالمرجع | `اجراء الاسم(بالمرجع الاسم: النوع)؛ { التعليمات };` |
| الأنواع الأولية | `صحيح`، `حقيقي`، `منطقي`، `حرفي`، `خيط_رمزي` |

## 3. التعليمات

```text
الاسم = تعبير؛
اقرا(الاسم)؛
اطبع(تعبير، تعبير)؛
اسم_الإجراء(المعاملات)؛
اذا(شرط) فان كتلة والا كتلة
طالما(شرط) استمر كتلة
كرر(متغير = بداية الى نهاية اضف خطوة) كتلة
اعد كتلة حتى(شرط)
```

تتبع الصياغة التي يعتمدها parser في المستودع. مثلًا، عامل الأكبر أو المساوي هو `=>`، وعامل القسمة الصحيحة هو `\`، وليس `>=` أو صيغة مخترعة بديلة.

## 4. التعبيرات والوصول

ترتيب الأولوية من الأعلى إلى الأدنى هو العوامل الأحادية، ثم `* / % \ ^`، ثم `+ -`، ثم المقارنة، ثم المساواة، ثم `&&`، ثم `||`. تشمل المقارنة `==` و`!=` و`<` و`>` و`=<` و`=>`.

يمكن الوصول إلى عنصر قائمة أو حقل سجل كما يأتي:

```text
القائمة[تعبير]
السجل.اسم_الحقل
السجل.قائمة[تعبير].حقل
```

## 5. القيم والرموز

الأعداد الصحيحة والحقيقية تُمثّل بأرقام عشرية. النص بين علامتي اقتباس مزدوجتين، والمحرف بين المحددين العربيين `‘` و`’`. القيم المنطقية هي `صح` و`خطأ`. التعليق الخطي يبدأ بـ`//` وينتهي بنهاية السطر. المعرف يبدأ بحرف عربي ويمكن أن يتبعه حرف أو رقم أو `_`.

## 6. مراحل التنفيذ

| المرحلة | النتيجة |
|---|---|
| Lexer | Tokens وlexical diagnostics مع موضع line/column/offset |
| Parser | AST typed وsyntax diagnostics |
| Semantic | scopes، symbol table، أنواع، lvalue، معاملات، استدعاءات، شروط وحلقات |
| TAC | Three-Address Code للتعبيرات والتحكم والوصول والاستدعاءات |
| Typed IR | تحقق من التعليمات والـ labels والقفزات قبل assembly/execution |
| Assembly | نص NASM-like مشتق من TAC وقابل للفحص الأكاديمي فقط في الوضع الحالي |
| Interpreter | تنفيذ داخلي وإخراج stdout من البرنامج الصحيح |
| dart-native | توليد Dart ثم `dart compile exe` وإعادة مسار executable الحقيقي عند النجاح |

## 7. معيار عدم الادعاء

وجود AST أو TAC أو Assembly لا يثبت امتلاك compiler native. لا يسمى الملف executable إلا بعد إنشائه على القرص واجتيازه فحص الملف. ولا يسمى الناتج Assembly binary ما لم يمر بمجمع Assembly فعلي.
