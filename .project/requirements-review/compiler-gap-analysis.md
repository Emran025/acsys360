# مصفوفة متطلبات مترجم مشروع العربية

## المصدر الأكاديمي

هذه المصفوفة مبنية على ملفي التكليف وقواعد اللغة الموجودين في `.project/requirements-review/`. التكليف يطلب أن تكون مخرجات المترجم ناتجة فعليًا عن تحليل البرنامج، وأن يعرض المترجم Tokens وParse/Syntax Tree وSymbol Table وSyntax Errors وSemantic Errors وThree-Address Code وAssembly Code، مع ملف تنفيذي عند نجاح الترجمة. كما يطلب عشرة أمثلة متنوعة على الأقل، ومحررًا مستقلًا يستدعي المترجم التنفيذي عبر واجهة منفصلة.

## القواعد الرسمية المثبتة

| المجال | القاعدة الرسمية |
|---|---|
| البرنامج | `برنامج اسم_برنامج؛ كتلة_برمجية .` |
| الكتلة | جزء تعريفات اختياري ثم قائمة تعليمات داخل `{ ... }` |
| التعريفات | ثوابت، أنواع، متغيرات، وإجراءات |
| الأنواع | `صحيح`، `حقيقي`، `منطقي`، `حرفي`، اسم نوع، وقائمة/سجل مركبان |
| الإجراءات | رأس `اجراء`، اسم، معاملات شكلية بالقيمة أو بالمرجع، وكتلة، مع إنهاء `؛` |
| التعليمات | إسناد، `اقرا`، `اطبع`، استدعاء، شرط `اذا ... فان ... والا ...`، وتكرار `كرر` أو `طالما` أو `اعد ... حتى` |
| التعبيرات | ربط منطقي `||`، مقارنة `== != < > =< =>`، جمع/طرح، ضرب/قسمة صحيحة/حقيقية/باقي/أس، وعوامل أحادية `+ - !` |
| الوصول | متغير، فهرسة قائمة `[تعبير]`، أو حقل سجل `.اسم_حقل` |
| القيم | أعداد صحيحة وحقيقية، نص مزدوج، محرف بين `’...‘`، `صح` و`خطأ`، واسم ثابت |
| المعرفات | حرف عربي ثم حروف/أرقام/`_`، مع السماح بالأرقام بعد الحرف؛ الكلمات المحجوزة لا تعامل كمعرفات |
| الرموز | `.` و`:` و`;` و`,` والأقواس `{}` و`[]` و`()`, والمشغلات المقررة فقط |
| الملاحظات | الكلمات المحجوزة ذات خط تحتها أزرق في مواصفة المادة، والرموز لها تمييز لوني مستقل؛ التطبيق يترجمها لا يفسرها كقواعد C-like |

## الفجوات الفعلية في الرأس الحالي

| المتطلب | الوضع الحالي | المطلوب |
|---|---|---|
| Lexer | يدعم جزءًا من الكلمات والرموز والأعداد والنصوص والتعليقات `//` | توحيد قائمة الكلمات والرموز مع المواصفة، ومعالجة المحارف والمواضع والأخطاء غير المغلقة بدقة |
| Parser | برنامج ومتغيرات وإسناد وطباعة وقراءة وشرط وطالما وتعبيرات أساسية | إضافة الثوابت والأنواع والقوائم والسجلات والإجراءات والمعاملات والاستدعاءات والفهرسة والحقول و`كرر` و`اعد ... حتى` وقائمة التعليمات الفارغة |
| AST | عقد قليلة للمتغير والإسناد والطباعة والشرط والحلقة والقيم | نموذج typed يغطي كل إنتاجات grammar ويحفظ SourceSpan لكل عقدة |
| Semantic | جدول global للمتغيرات وفحص تعريف الاسم فقط | scopes متداخلة، ثوابت، أنواع، سجلات، قوائم، معاملات، استدعاءات، توافق الأنواع، lvalue، الشروط، والتكرار |
| Symbol table | رموز متغيرات فقط | kind/type/owner/parameters/fields/references ومخرجات قابلة للعرض |
| Three-Address Code | للإسناد والطباعة والشرط وطالما فقط | توليد كل التعليمات والتعبيرات والوصول والاستدعاءات بتسميات مؤقتة مستقرة |
| Assembly | غير موجود في `CompilationResponse` الفعلية | backend assembly نصي حقيقي ناتج عن TAC، أو target موثق قابل للتنفيذ على منصة البناء |
| Executable artifact | `artifacts` تعاد فارغة دائمًا | تعريف عقد artifact وإنتاج ملف تنفيذي أو runner قابل للتشغيل عند نجاح الترجمة، مع عدم الادعاء بإنتاج EXE إذا لم يوجد backend فعلي |
| Project compile | يترجم الملفات منفردة ويكشف duplicate names محدودًا | بيئة رموز مشتركة، entry point، استدعاءات بين الملفات، وأخطاء project ذات source path دقيق |
| Protocol | الحقول اللازمة موجودة لكن assembly/artifacts وأنواع الرموز ناقصة | ملء الحقول الحالية دون كسر protocol version، وإضافة metadata فقط عند الحاجة وبإصدار واضح |
| Tests | اختبارات smoke وحالات بسيطة | golden tests تغطي كل إنتاج grammar، negative tests لكل نوع خطأ، ومخرجات ثابتة قابلة للمراجعة |

## قرار هندسي

لن نضيف syntax غير موجود في ملف القواعد، ولن نسمّي interpreter أو pseudo-assembly ملفًا تنفيذيًا حقيقيًا. التنفيذ سيكون على دفعات: أولًا تثبيت grammar وAST والـ spans، ثم semantic typed، ثم TAC، ثم backend موثق قابل للاختبار، ثم protocol وواجهة المحرر. كل دفعة يجب أن تضيف أمثلة ناجحة وفاشلة ومخرجًا ناتجًا من المصدر الفعلي.
